# Deployment and operations

Last reviewed: 2026-09-02

## Production model

- Platform: Cloudflare Pages.
- Canonical origin: `https://www.allyachtservice.com`.
- Expected production branch: `main`; verify the connected project before changing it.
- Build command: the current `build` script in [`package.json`](../package.json).
- Output directory: `dist`, configured in [`wrangler.jsonc`](../wrangler.jsonc).
- Framework preset: Astro; repository root is the build root.
- Static pages/assets are generated by Astro; `/api/*` is handled by Pages Functions.
- Node/npm requirements come from `.nvmrc` and package engines.

Do not hardcode Cloudflare UI choices here when they can drift; verify the current project settings before changing them.

## Environment names

Production/Preview build and runtime settings use these current names:

- Public build variables: `PUBLIC_SITE_INDEXABLE`, `PUBLIC_TURNSTILE_SITE_KEY`.
- Non-secret runtime variables: `CONTACT_FROM_EMAIL`, `CONTACT_TO_EMAIL`, `TURNSTILE_EXPECTED_HOSTNAMES`.
- Encrypted secrets: `TURNSTILE_SECRET_KEY`, `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, `GOOGLE_OAUTH_REFRESH_TOKEN`.

Values belong in the provider's environment/secret UI, not documentation or git. See [Security and Secrets](SECURITY_AND_SECRETS.md).

## Indexability environments

`PUBLIC_SITE_INDEXABLE` is evaluated at build time. Use `false` for a preview-safe artifact and `true` for the production/indexable artifact. An indexable build also runs the legal completeness guard in [`src/data/legal.ts`](../src/data/legal.ts). A production deployment must be checked for `index, follow`; the 404 remains `noindex, nofollow` in both modes.

## External DNS and duplicate-host context

Owner-supplied current context:

- authoritative DNS remains at Namecheap;
- `www` resolves to the Cloudflare Pages project;
- apex `allyachtservice.com` permanently redirects to `https://www.allyachtservice.com/` with the path preserved;
- `allyachtservice.pages.dev` redirects to the canonical `www` origin to prevent a duplicate public site.

**Verify in provider UI before changing; repository code alone cannot prove current provider state.** Do not modify Namecheap, Cloudflare redirects or Search Console without explicit authorization.

## Deployment checklist

1. Inspect the current worktree and expected diff.
2. Run the change-appropriate checks and full pre-deployment suite in [Testing and Quality](TESTING_AND_QUALITY.md).
3. Build once with preview-safe indexability and once with production indexability; inspect robots metadata and the legal guard.
4. Compare generated routes and sitemap against the intended change.
5. Check that no credential, local environment file or unintended generated artifact is tracked.
6. Commit and push only through the normal owner-approved workflow.
7. Confirm the Cloudflare deployment completes for the expected commit.
8. Verify representative production EN/ES/RU routes, canonical/hreflang, assets, 404 and sitemap.
9. When Contact changed, submit a controlled production enquiry and verify mailbox delivery, Reply-To and safe logs. Do not expose test personal data unnecessarily.
10. For a priority new page/article, use Search Console URL Inspection after the live page and sitemap are verified.

## Rollback and incident posture

Cloudflare deployment history and git provide the normal recovery path. Do not rewrite git history or delete deployment records as a first response. For Contact failures, preserve direct phone/WhatsApp/email options, inspect sanitized Function logs and verify external Turnstile/Gmail dependencies before changing validation.

## Local Cloudflare preview

The current `preview:cloudflare` package script builds then runs `wrangler pages dev dist`, including Pages Functions. It requires local variables/secrets appropriate to the test being performed. The ordinary Astro preview serves static output but does not reproduce the Cloudflare Function runtime.
